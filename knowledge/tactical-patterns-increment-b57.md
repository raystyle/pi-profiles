# 战术模式增量:campaign 语料实证(P1-P10 复现与新候选)

> 层位:[[tactical-patterns]](seed,P1-P10)与 [[web-vuln-methods]] 族矩阵之间的战术模式层**增量**。seed 不动,本件是单向链下游的项目层候选,编审后并入。
> 语料:另一条线(疾影线)PortSwigger 实战实录 155 篇(编号 01–156,缺 42/43 = 官方协作器依赖的挂起对),逐篇读完;并读该线台账/封锁清单/边缘分类学。蒸馏批 57。
> 计数记法 `疾影 n / pi m`:pi 计数取自 seed 各条 `实证(N)`(seed 实证题号全为 pi 线实录);疾影计数为本批新证。
> 件双写为「能力面(catalog 实名件)」;`psw_*` 是本线件,不在本仓 catalog。
> 覆盖缺口(全语料正则核实):本线 **0 题**请求走私、0 题缓存投毒、0 题原型污染、0 题 GraphQL、0 题 LLM。

## 一、P1-P10 复现实例(疾影线)

### P1 写侧证窗 → 读侧播撒 —— 疾影 1 / pi 3
- 55:校验健全但**先落盘后校验**,以密集并发上传造落盘窗、并发读线程在清除前抢读。
- 变体注:本线尚未出现「写侧齐发 + 读侧按时长播撒」的完整两段式;55 只有写侧窗口,读侧是争抢而非播撒,且未用单包原语。
- 反例:无独立反例;55 自述未走 P2 单包路线。

### P2 真单包并发原语与预算律 —— 疾影 2 / pi 2
- 154:登录失败计数「检查与递增非原子」,窗为内存计数**亚毫秒**;终以手工组 HTTP/2 帧(三十流头块拼一大缓冲一次写 + 门控后末字节帧一次写)同窗齐抵,命中流返回 302 取口令。
- 156:折扣校验与已用标记间竞态,窗为**存储写延迟**量级;h2 单连接多流各持缺末字节请求门控齐放,叠算折扣过线。
- 变体注(重要):本线把预算律读成**末字节同步粒度**——154 首写 9500B 一次写仍成窗,同刻由门控后末字节 300B 一次写保证。判的是「最后一字节同刻」,不是「整请求 <1400B」。
- 反例:154 —— 库级 h2(逐流独立 TLS 记录)三十流全 200 中零,TLS 多连接齐发同样中零(跨连接抵达散布毫秒级);逐帧串行的 CDN 后端吃掉单包收益。

### P3 第一跳 desync 计数 oracle —— 疾影 0 / pi 3
- 本线无走私族实录,零覆盖(该族是 pi 独占)。
- 最接近的形态是 11 号「前端按路径拦截、后端按改写路由头解读」,属**单请求内两字段维的解读分离**,不是连接内失步计数(该题自述已排除 P3)。

### P4 未完成帧 → 下一请求补全 → 读交接响应 —— 疾影 0 / pi 5
- 同 P3 的覆盖缺口,本线无实证也无反例。

### P5 无回显换信道:三梯 oracle + 控制值标定 —— 疾影 19 / pi 4(本线最大富矿)
- 错误文本梯:65(子查询值 CAST 进类型失配错误文)、67(条件式控除零分支,真 500 假 200)、117/118/119(外实体展开的本地文件经 400 错误消息带出)、124(文件值拼进不存在文件路径,错误消息**路径段**即数据,全程免外呼)、125(无攻击服时重定义本地 DTD 既有实体,错误路径引爆)。
- 布尔条件响应梯:64(条件真值时页面命中串在场,逐位二分)。
- 时延梯:38(请求步时毫秒作计时器,先打无注入基线对照)、66(字面拼接挂起函数,基线标定门限后只取过线)、71(条件式真值分支睡固定时长,逐位二分提数)、100(有效名对应的人工延迟随口令长度**线性增长**,超长口令放大斜率 + 中位差分)。
- 带外梯换形:39(命令输出重定向落盘到 web 可服务目录,再经页面既有资源加载参数通道取回全文)。
- 结构/编码换信道:142(输出受过滤,改以**十进制码点**回显再转文本)、15(内层字段选择以 500/400/200 状态码分层 + 已知真值基线标定)。
- 存在性枚举梯:20(失败文案区分账户存在性)、21(差分只差一个标点/空白,须先以已知真假对照标定真差分字节)、23(命中与未命中以文案换形区分)、25(锁定文案只在真实账户出现)。
- 变体注:本线把 P5 从「盲注入专用」扩成**跨族通用 oracle 换信道律**——认证枚举、XXE 报错、命令注入时延、SSRF 回显都落同一律。
- 边界/半场(仅「控制值标定」半,回显面本已开放,不计入实证):57/60/68/70(UNION 与短路题的基线计数对照)、108/109/116(防护成分的裸形对照)。
- 反例:66 —— 纯挂起即判解,「布尔 WHERE 先匹配一行」不在场;68 布尔短路题不需要行匹配;72 及全部 UNION 回显题有回显,不属换信道;71 记「实例过热时连发普遍变慢,秒级差分不足即不可判」。

### P6 键面三问 → 未键控面 → 续毒保活 —— 疾影 4 / pi 6(两面性质不同)
- 138/139/140/141:全部落在**缓存欺骗**的读取侧——138 缓存按静态扩展名规则收响应而源站以正则端点把账户路径任意后缀映到会话页;139 缓存按目录前缀收且不解码而源站解码编码点段后回溯;140 源站以某字符为界符截段而缓存对该编码界符与点段归一化后回溯;141 源站认界符截段而缓存不认该界符、按尾部扩展名收。
- 变体注:本线把键面三问用于**读取侧**,判据是 X-Cache 命中头(命中头直证),内容回显只是次级确认;pi 的 6 题在投毒侧(键注入 + 续毒保活)。两侧共享「键分量 ≠ 渲染分量」,不共享注入与保活。
- 反例:本线 0 题缓存投毒,无投毒侧实证可对照。

### P7 字节级请求行投毒 —— 疾影 6 / pi 3
- 92b:载荷含百分号编码换行,高层库通道返 400,须换浏览器引擎面直发(传输层处理差异)。
- 131:后缀黑名单只看最终名,文件名放**编码空字节 + 白名尾缀**,校验见白名、落盘层截断还原可执行扩展。
- 139/140/141:路径点段与界符的编码/归一化差异。149:下游对值做 URL 解码致流坏,发送侧预编码后达执行。
- 变体注(重要):本线 P7 主要是**路径/值语义层的编码差**,不是 pi 那种「请求行原字节」;共同机制是「某一层的重编码/归一化吃掉载荷」,面不同。
- 反例:132 —— 体为二进制,无需字节级编码规避;131 附记裸空字节在头层即被拒,须编码形。

### P8 OOB 判定两半:到达即判定 / 自持标签读回 —— 疾影 6 / pi 4
- 检测半:98(盲代取面以引用头作代取地址,请求命中出纤放行域即判解,自建域作负对照)、120(盲面外实体指向放行域唯一性子域,判据是横幅翻而非响应体)、121(常规实体被过滤改 DTD 内参数实体自调,只证到达)、127(盲注借数据库 XML 解析能力在查询期出网,只证到达)。
- 读取半:123(参数实体二级嵌套把文件值拼进外呼 URL,证据取自自持攻击服访问日志)、152(跨站握手无来源校验,协议初始化命令触发服务端历史回放,回放面即外泄面)。
- 变体注:本线把读取面的载位从「自持 secret 派生标签」改判为**载位选择律**——带值返回的载位三选(本地错误文本最稳 / 自持攻击服查询参 / 子域标签)。
- 反例:123 —— 子域标签载位**首次证伪**:值含换行致主机串非法、解析即死零外呼,改查询参载位方通;120/121 检测型题无读取面需求。平台侧:自建任意外部域对 lab 不可达(98 实证),仅官方放行域可判——与 pi 线独立同证。

### P9 用户激活载荷必须真手势 —— 疾影 5 / pi 2(语义分叉)
- 44:属性上下文引号未编码可逃逸,事件属性随引号进标签,判读以真鼠标派发触发。
- 138/139/140/141:缓存欺骗的交付腿须先落载荷页,再经平台 UI 真点投递给受害者。
- 变体注:pi 的 P9 是「**载荷执行**需真手势」;本线 138–141 是「**投递**需真手势」——程序面 POST 投递返回 302 但不生效,只有平台投递钮有效。同一「合成动作不算数」的机制,作用在两个不同阶段。
- 反例:126/128/129/130 记脚本面直发投递全部无效;34 页内合成 a.click() 未落地新开页(引擎抑面),与用户激活同形而实为引擎行为,属读法边界。128/129 另证载荷可由宿主页外部刺激(外锚点聚焦 / iframe 改宽 resize)免手势引爆——「需手势」不是全族铁律。

### P10 渲染面判读:先聚焦、再读副作用 —— 疾影 3 / pi 3
- 89:拾值面直拼模板源码,注入须先闭合定界符再自包裹成表达式,且须**经另一渲染面触发**后才读得到(只设值无触发面即假阴性)。
- 128:标签挂聚焦事件需 tabindex 才可聚焦,由外部页地址尾挂锚点触发落地自动聚焦引爆。142:沙箱逃逸输出受过滤,改以十进制码点回显再转文本。
- 变体注:本线把「先聚焦」泛化为**触发面**——异步渲染/事件管线必须另有一次触发投递;并补「输出过滤时改编码回显」这一判读面。
- 反例:145–149(反序列化五题)执行副作用不在响应体内,渲染面判读不适用,须改看独立判定面(见候选 C8)。

## 二、新模式候选(本线有、P1-P10 未覆盖,跨题 >=2;结构同 seed)

### C1 客户端可控维即权限边界 —— 实证 03,05,06,07,08,13,19,22,23,32,133,143,144,145
- 判型触发:同一动作换一个**客户端可任意置换的分量**就从拒绝态转受理态(方法/头/cookie/请求体字段/查询参数/令牌声明)。
- 机制原理:权限判定挂在客户端可控维而非服务端会话派生值;服务端把请求内声明的身份/权限/类型当权威。
- 件组合:逐维差分(状态码差分能力:`http_dump`、请求序列能力:`reqseq`/`psw_reqseq`);凭据组合枚举(cred_matrix)。
- 反例:无(14 题同向);边界:05 只在方法维,08 只在 cookie 维——维是实例属性,判定点才是机制。

### C2 缺步缺态默认放行 —— 实证 09,18,29,32,35
- 判型触发:多步流程中删掉某步、或删掉某必填参数整体提交,不报错反被受理。
- 机制原理:「未到达某步骤 / 未携带某参数」被服务端当作默认最宽授权态(缺省 admin、跳过验证码页、缺参落无校验分支)。
- 件组合:步骤序列对照(reqseq 前后步差分)、字段整删 vs 置空对照(form_sweep)。
- 反例:32 —— 空串形仍在场走修改路径被拒,缺参是**删键**而非置空;两者不等价。

### C3 披露面优先侦察 —— 实证 02,04,12,14,17,85,86,87
- 判型触发:功能入口/端点/秘密不在可见链路上,但站点存在公开披露面。
- 机制原理:入口与秘密先经披露面取得再下钻——爬虫声明文件、内联脚本与 JS 引用、接口文档、公开链接、OPTIONS 的 Allow 头、提交历史、页内注释、备份文件路标。
- 件组合:页面抓取与文本手术(page_read/web_fetch + text_grep)、内容枚举(search_content、find_files);对懒渲染清单页须两拍后再读链接。
- 反例:87 —— 公告文件 404 无线索,路标改在页内注释;披露面缺位不等于无入口。

### C4 校验面与使用面取值不一致 —— 实证 47,48,50,72,94,95,131,139,140,141
- 判型触发:同一串在两层被解出不同值(过滤层 vs 执行层、缓存层 vs 源站层)。
- 机制原理:层序(过滤先于解码)、遍数(单遍剥除不回扫)、截断(C 串空字节)、归一化(点段/界符/编码)任一处两侧口径不同,即产生两串分叉;控制-变体归因链(先提被拒形立实证,再加绕过变体)定位是哪一层。
- 件组合:成组变体对比(raw_matrix、url_fuzz 分隔符族、header_scan)、字节级重放(raw_http、conn_reuse --send-str);WCD 侧判据用缓存命中头(cache_probe)。
- 反例:132 —— 体为二进制,编码差面不存在;141 —— 裸写界符两侧同解即形态失效,必须编码加预补偿。

### C5 业务数值域只比总量上限 —— 实证 27,28,30,33,36
- 判型触发:结账/兑换面只校验合计与余额,不校验条目合理性与符号。
- 机制原理:金额域缺条目级校验(负数量、客户端提交价、有符号整型聚合卷绕)且总价无下界;折扣叠加与兑换回路构成正反馈。
- 件组合:表单字段扫描(form_sweep)、请求序列循环(reqseq 循环展开;循环驱动件如 money_loop 属本线/catalog 混合)。
- 反例:30 —— 负合计被 err=NEGATIVE_TOTAL 显式拒,第一负带不可结算,须推过 2^32 到第二正带;36 量购放大器实测码列不规则,弃用退为每单一张。

### C6 限速对抗:计数重置与目标解耦 —— 实证 24,25,99,102
- 判型触发:失败计数按来源/账户记账,或锁定检查先于认证。
- 机制原理:计数重置条件与目标解耦(任一账户成功即清零)⇒ 交错序列把计数压在阈下;锁定窗口感知重试同候选可穷尽空间;参数类型错位(数组装箱)可把 N 次尝试压成一次请求。
- 件组合:节奏化重复请求(cred_matrix 生成、请求序列 + 定时件 nap)、窗口标定(header_scan 轮换源地址头)。
- 反例:24 —— X-Forwarded-For 不被记账,源地址轮换面实证为零;封锁检查先于认证 ⇒ 窗口内自有正确凭据也被拒,交错重置只作用于计数不能解已触发封锁;99 封锁页与全错页同为 200,批量 200 不可即断未命中。

### C7 判据取自客户端可控头 —— 实证 06,84,101,151,152,155
- 判型触发:来源/特权/转发/宿主判据取自请求头。
- 机制原理:头是客户端可控面——判据缺失(无来源校验)、只做部分形(只比前缀/首尾片段)、或把某个头值当特权标识(内网环回名)即被伪头或跨站页面绕过。
- 件组合:头族扫描(header_scan、header_fuzz)、跨站握手能力(ws_chat)、字节级重放(raw_http)。
- 反例:155 —— 仅环回名值通、内网段值不通,判据是「头值 × 登录态」两态而非「连接态松弛」;84 回显泄露的真实出口地址不可用,须改环回值才放行。

### C8 执行态判读改看独立判定面 —— 实证 41,44,89,127,128,129,145,146,147,148,149
- 判型触发:触发成功的即时响应是异常态(5xx/空体)或副作用不在响应体内。
- 机制原理:执行成功与响应形态解耦 ⇒ 判定改看独立判定面(实例横幅、缓存命中头、攻击服日志、主世界旗标);旗标为零先分离三因:载荷语法错(静默)、触发条件不满足、读道错世界。
- 件组合:页内判读(browser_suite eval、page_alert、page_eval_batch)、独立判定面读取(page_read 语义面 + 横幅件)。
- 反例:145 改指非图文件后账户页恒 500,页面判读不可用,只以删户动作定判;147 链生成器单给命令报参数错,须函数加参数的调用形式。

### C9 三段序:布线 → 投递 → 读取不可倒置 —— 实证 134,135,136,138,139,140,141
- 判型触发:利用链要过第三方(受害者浏览器/模拟访客),读取面与投递面分离。
- 机制原理:先落载荷页、再投递、最后独辟读取面取外携值;顺序颠倒则读取空跑(投递受理与读取之间有模拟访问时序)。
- 件组合:载荷托管 + 请求序列(reqseq)、受害者投递走平台 UI 真点、读取面轮询。
- 反例:138–141 读取面早读只得 miss,须待投递受理后再读;投递后横幅可能因确认页重定向延迟数秒未翻。

### C10 自述信任锚 —— 实证 74,76,77,78(73 为退化形)
- 判型触发:令牌/对象自述其验签或权限依据。
- 机制原理:验签所需的算法、密钥材料或密钥来源取自被验对象自身,服务端不校验出处;退化形是完全不验签。
- 件组合:令牌构造与重签(jwt 件)、声明字段改写(http_session/reqseq)。
- 反例:78 —— 绝对路径形与两层相对回溯形取空设备文件均拒,只三层形命中;被拒不等于面不通(见 C13)。

### C11 载体选型律(可控面 + 过滤缺口 → 注入形态) —— 实证 119,121,123,124,125
- 判型触发:同一解析面在不同可控粒度/过滤强度下可用形态不同。
- 机制原理:注入形态随「可控面 × 过滤缺口」切换——全文档可控用经典实体;无全文档控制权则往参数值槽注内联包含元素;常规实体被拦则用 DTD 内参数实体;无攻击服则重定义本地 DTD 既有实体(首声明胜)。带值返回的载位同样三选。
- 件组合:载荷变体成组投递(raw_matrix)、本地 DTD 素材取自本机文档克隆而非题面直构。
- 反例:125 —— 实体名须是本地 DTD 内既有名,自造名无引用点;123 子域标签载位对含换行的值解析即死。

### C12 窗宽分层 → 并发原语配型 —— 实证 154,156
- 判型触发:竞态动作恒 miss,但窗口存在已被证。
- 机制原理:窗按成因分层——**存储写延迟窗**毫秒级散布仍可穿,**内存计数窗**亚毫秒须真同刻;先标定窗宽再配原语(宽窗用库级单连接多流门控,窄窗须手工组帧末字节同步)。与 P2 的关系:P2 只说「用单包」,本条补「先判窗宽决定是否需要单包」。
- 件组合:单包并发原语(h2_burst)、预热连接齐发(race_send)、读侧播撒(race_spread);窄窗需手工组帧能力(本线 psw_race_login_sp,非本仓 catalog)。
- 反例:156 低并发 25–40 发窗内仅命中 2–3 发不达线,并发须贴窗宽;154 限时耗尽即失败态须重启实例。

### C13 同面多形逐投:被拒不等于面不通 —— 实证 46,47,50,74,78,80
- 判型触发:目标面在首选形态被拒。
- 机制原理:同族载荷按形逐投,先前诸形被拒只是「该形不适用」,不是「该面不通」;以单变量差分收敛到命中形(短写法/双重编码/层叠回溯/前缀正则 vs 锚定正则)。
- 件组合:成组变体对比(raw_matrix、url_fuzz)、逐形重放(conn_reuse)。
- 反例:48 —— 请求构造层首轮 400 与浏览器面真值相抵,须以靶场真值裁决并当场修件(斜杠归一只作用路径段,查询值双斜杠保形)。

### C14 免手势自动引爆(外部刺激代餐用户手势) —— 实证 128,129
- 判型触发:载荷需要聚焦/resize 等事件才能引爆,但题面硬性要求免交互(或投递链不允许真实手势)。
- 机制原理:由**宿主页对目标页施加外部刺激**(跳板页地址尾挂锚点使落地即自动聚焦 / 外框 iframe 改宽触发内窗 resize),在零受害者手势下把事件送上管线——事件仍是真事件,只是触发源换成另一个文档。
- 件组合:页内判读与真输入(browser_suite、page_alert)、宿主页构造(载荷托管 + 受害投递)。
- 反例(重要读法边界):128 —— 自查通道(无头引擎)下地址片段自动聚焦**不触发**,须手动点火,而受害投递链落地即聚焦;不得据自查侧零结果判负。129 —— 判定函数逐题实读,弹窗信标法失效。

### 家族内候选(>=2 题但未升层,逐条附理由)
- 文本位探针(58,59,70):UNION 回显时逐列放试值定文本兼容位再选读法——SQLi 族内形态,机制已被 C4 的校验/使用分歧覆盖。
- 结构名回填两跳(62,63):表名列名随机化,须先枚举读出真名再回填取数——SQLi 族内。
- 尾形与壳配对律(60,67,68,69):注入值会被外围拼装壳再包裹,载荷尾须与壳剩余片段凑成合法语法——SQLi 族内,同属 C4 的「两侧口径差」在语法层的实例。
- 注入载体自响应头取值(64,65,66,67,71):注入点不在题面参数,先从响应 Set-Cookie 读分析 cookie 值再回注——SQLi 族内。
- 方言先判型链(60,61,67):整梯同形假阴本身即方言证据(须 FROM/须白尾/挂起函数缺失),先判型再上载荷——SQLi 族内。
- 载荷装配自检(65,70,72):载荷生成器自身缺陷(丢尾段、双百分号、重复头名)造成静默假阴,先以控制值验证载荷完整——已属 C8 的「假阴性三问」子面。
- 回显型代取回注判证(93,94,95,96,97)与同信道写后复读证零(93,95,96,97):内部面响应回注页面即可达判据;写操作后用同一通道复读同一面、以目标条目消失为受理直证——SSRF 族内,机制上属 C8 判定面。
- 命中头作缓存面直证(138–141):以 X-Cache 命中头为「缓存面成立」的原语证据,内容回显只作次级确认——已并入 C4 件组合。
- 编码预补偿选中一侧(139,140,149):发送侧先编码使下游只有目标那层解码——C4 的施法面。
- 可逆凭据离线还原(26,103):驻留凭据是可离线推导的确定性构造,取一枚样本清构形后离线预造全量重放——认证族内,与 C6 的批量面相邻但独立。
- 可达执行落点(53,54):落点不可执行时换落点(遍历换目录、等价扩展换解释器)以抵达被解释执行面——与 C13 同源(形态选择),未再升层。

## 三、双线解法差异(pi 独立线 vs 疾影线,同题对照)

- **host-header SSRF via flawed request parsing**:pi 记 solved(绝对请求行 + Host 头 + 实例 `_lab` cookie);疾影线记「现代边缘墙击杀」挂起。分歧点是那个 `_lab` cookie——同一 infra 的两种断言,pi 侧是后验订正。
- **IDOR 记录越权**:同机制;pi 先离线解本机 Chrome cookie 复用 OIDC 取会话再枚举对象引用,疾影线走浏览器表单登录后对记录号邻域试探——差异在会话获取手段与枚举件。
- **无防御 CSRF**:pi 借存储型 XSS 在同源受害者会话内取令牌再 POST;疾影线走攻击服自动提交表单直打无令牌端点——差异在是否需要同源取令牌。
- **盲布尔 SQLi(条件响应)**:两线取载体相同(响应 `Set-Cookie` 里的分析 cookie 值),差别只在件(pi `blind_oracle` vs 本线提取器)。
- **SSRF 黑名单**:同用紧凑环回 + 路径编码;pi 单次 URL 编码,疾影线路径首字母**双重**编码并把官方两步探测链压成一条载荷。
- **SSRF 白名单**:分隔符选型不同——pi 用 `%23`(#),疾影线以斜杠形为主线,两形实测皆通。
- **无限资金逻辑**:同回路;pi 用件驱动批量循环,疾影线因量购码列不规则弃用放大器、退为每单一张的定量循环——差异是批量面的可用性。
- **跨站 WebSocket 劫持**:两线都无需 CSRF 令牌(会话 cookie + 无来源校验);pi 用 Image 信标外带帧,疾影线走攻击服日志取回。
- **竞态限速绕过**:pi 未覆盖此题;疾影线记库级 h2 与 TLS 多连接**都不成窗**(逐帧串行),须手工组帧——pi 线未遇此墙(P2 变体注的分歧来源)。
- **反序列化 PHP 自建链**:两线都先读源码备份;pi 手工拼序列化串(踩私有属性名长度差一位的坑),疾影线对同族题走析构执行面。
- **反序列化 Java**:gadget 来源档位不同——pi 自写类源 + javac 编译输出,疾影线用第三方工具预建通用集合库链,且多一层「下游 URL 解码致流坏、发送侧须预编码」的通道补偿。
- **OAuth 令牌窃取**:两线都用路径穿越过回调白名单;pi 直指代理页,疾影线借站内开放重定向二跳再转查询参。
- **SameSite Strict 绕过**:pi 用兄弟域登录反射 XSS 当跳板(Strict cookie 在同站兄弟域仍发),疾影线用站内客户端重定向一跳回收 cookie。
