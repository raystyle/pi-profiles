## The one serious finding: a starved renderer wedges the whole desk

Reproduction: breakpoint on a page line whose next statement calls a JS busy-spin (`spin(25000)` = `while (performance.now() - t < ms) {}`, re-armed every tick so the renderer never yields), then `step` (over) that call.
- Client: `{"action":"dbg_cli","error":"step: reply: Resource temporarily unavailable (os error 11)","success":false}` after the 20s step read window (EAGAIN).
- Then EVERY client command timed out the same way - `read`, `status`, again after minutes - so the documented diagnosis ("read the ledger first to judge the frame") is unavailable through the desk. Reading the ledger FILE directly is the only working path and shows the truth: last rows are `Debugger.resumed` seq 18 and nothing after; the step's pause never landed => the frame was never stopped (page is running, exactly as the note says).
- Desk state while wedged: process alive, `ps -L` shows all 3 threads in `futex_do_wait` (not idle-parked, not looping: 0% CPU), event pump frozen (ledger mtime stops), and it never recovered - not after the spin, not after closing the page target entirely (renderer gone). Recovery required `kill -9` on the daemon: `stop` is a client command and therefore also EAGAINs.
- Contrast that isolates the cause: a merely *pending* CDP call does NOT wedge the desk. With `net intercept --hold` a `Page.navigate` reply also EAGAINs on the client (the page waits on the held request), yet `read`/`status` kept answering normally throughout. So the wedge needs renderer starvation, not a pending call.
- Candidate fix direction (untested): the desk kills a step's own CDP await and/or moves the transport off shared std locks; at minimum `read`/`status` and the event pump should be independent of a pending CDP reply.

## Recipes

Isolated chrome for desk acceptance (never the shared engine-profile):
`setsid ~/.browse-rs/chromium/<pinned>/chrome --user-data-dir=/tmp/<x>/profile --remote-debugging-port=<port> --no-first-run --no-default-browser-check --no-sandbox --headless --noerrdialogs --ozone-platform=headless --ozone-override-screen-size=800,600 --use-angle=swiftshader-webgl file:///tmp/<x>/page.html > chrome.log 2>&1 < /dev/null &`
Recreate a closed page target at the browser level (works while the desk is wedged): `curl -s -X PUT 'http://127.0.0.1:<port>/json/new?file:///tmp/<x>/page.html'`.
Test-page design that drives breakpoints by itself: `setInterval(bump, 800)` for the bp line, a second `setInterval` calling a labeled-loop function, and a slow tick gated by a `slowMode` flag flipped via `send Runtime.evaluate` (the EAGAIN trap). `wait --until paused` with no `--since` returns the whole pause history, so pass `--since <seq>` when only the new stop matters. `wait --until <Domain.method>` matches subscribed methods by substring; default `since` is the current watermark, so an event that already landed is missed unless you read the ledger.
Running the real client with a caller directory of your choosing: `cd <dir> && rust-script ~/.pi-rs/agent/rust-materialized/dbg_cli.rs --socket <sock> proc-start <name> -- ./relative-binary` (rs_execute always runs from the repo root, so this is how the F1 caller-cwd fix gets exercised).
